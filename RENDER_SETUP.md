# Пробный запуск Nimb на бесплатных сервисах

Этот вариант предназначен для небольшого тестирования с друзьями. Он не заменяет аудит безопасности и полноценный продакшн-хостинг. Не отправляйте в чат пароли, ключи, токены и строку подключения к базе: вводите их только в настройках сервисов.

## Что понадобится

- Аккаунт Render, подключённый к GitHub: бесплатный веб-сервис для сайта и API.
- Проект Supabase Free: PostgreSQL и приватный bucket для файлов.
- Аккаунт Brevo: отправка писем подтверждения и восстановления по HTTPS. Для отправки может потребоваться подтверждение адреса отправителя и активация транзакционных писем со стороны Brevo.

У бесплатного Render приложение засыпает при отсутствии активности и при следующем открытии просыпается с задержкой. У бесплатного Supabase есть лимиты и приостановка неактивного проекта; автоматических резервных копий на бесплатном тарифе нет. Создавайте отдельные резервные копии. Условия провайдеров могут измениться.

## 1. Supabase

1. Зарегистрируйтесь на https://supabase.com/ и создайте бесплатный проект. Пароль базы сохраните у себя.
2. В проекте откройте **Connect** и выберите PostgreSQL **Session pooler**. Скопируйте полную строку соединения с паролем для переменной `DATABASE_URL`; используйте TLS. Подключение Session pooler работает по IPv4. Пароль со специальными символами нужно URL-кодировать.
3. В **Storage** создайте bucket с именем `nimb` и оставьте его **private**.
4. В настройках Storage откройте S3 connection, создайте пару S3-ключей и сохраните endpoint, region, access key ID и secret access key. Они вводятся только в Render.

## 2. Brevo

1. Зарегистрируйтесь на https://www.brevo.com/ и подтвердите отправителя. Проверьте, что транзакционные письма разрешены для аккаунта.
2. В настройках создайте API-ключ Brevo. В Render задайте `BREVO_API_KEY` и адрес подтверждённого отправителя `BREVO_SENDER_EMAIL`.
3. Если провайдер заменит адрес отправителя или запросит проверку домена, выполните его требования. Отправку произвольным адресатам необходимо проверить реальным письмом; без успешной отправки зарегистрироваться нельзя.

## 3. Render

1. Откройте https://dashboard.render.com/ и подключите GitHub-репозиторий с исходниками Nimb.
2. Создайте Blueprint из файла `render.yaml` в ветке с подготовленными исходниками. Убедитесь, что выбран план **Free**; не выбирайте платные ресурсы.
3. На экране переменных заполните:
   - `DATABASE_URL` — строка PostgreSQL Session pooler из Supabase;
   - `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` — параметры приватного bucket;
   - `BREVO_API_KEY`, `BREVO_SENDER_EMAIL` — настройки Brevo.
4. Запустите создание сервиса. Render соберёт Docker-образ, применит миграции и выдаст адрес `https://...onrender.com`. `RENDER_EXTERNAL_URL` автоматически используется как адрес сайта. Для собственного домена понадобится дополнительно задать `APP_ORIGIN` равным точному адресу с `https://`, без завершающего `/`.
5. После развёртывания зарегистрируйте свой аккаунт и проверьте письмо подтверждения. Найдите свой числовой ID в профиле. В настройках сервиса Render добавьте `ADMIN_USER_IDS` со своим ID и перезапустите сервис.
6. Проверьте регистрацию второго человека, личную переписку с двух устройств, загрузку картинки, восстановление пароля и настройки приватности. Только после этого делитесь ссылкой для пробного тестирования.

Все переменные с ключами вводятся в приватных настройках Render. Не добавляйте их в GitHub, ZIP-архив и сообщения. Поддержка обычного SMTP оставлена для других серверов; бесплатный Render блокирует SMTP-порты 25, 465 и 587, поэтому здесь используется Brevo API.
