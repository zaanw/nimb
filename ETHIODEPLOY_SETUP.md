# Пробный запуск Nimb на EthioDeploy

Этот вариант рассчитан на бесплатное тестирование с небольшой группой, а не на надёжный публичный сервис. Он ещё не проверен развёртыванием у провайдера.

## Что понадобится

- Аккаунт EthioDeploy с подключённым GitHub. По документации платформы на Free есть один проект, 256 МБ памяти и остановка после 30 минут без запросов; сайт может открываться с задержкой.
- Приватное S3-совместимое хранилище, например Supabase Storage Free: файлы на диске приложения после перезапуска не сохраняются.
- Подтверждённый отправитель и доступ к транзакционным письмам Brevo для регистрации и восстановления пароля.
- База PostgreSQL — можно подключить Postgres addon самого EthioDeploy, который добавляет `DATABASE_URL`, либо использовать Supabase.

## Подготовка проекта

1. Войдите в https://ethiodeploy.com/ через GitHub. При установке GitHub App выберите только репозиторий `zaanw/nimb`.
2. Создайте Web Service и укажите исходники ветки `nimb-ethiodeploy` как основную ветку проекта, если платформа позволяет её выбрать. Бесплатный тариф не включает отдельные preview-развёртывания веток; не включайте платный тариф. Если настройки основной ветки нет, уточните у поддержки, как указать исходную ветку. Не меняйте основную ветку чужого репозитория вслепую.
3. По возможности при создании отключите автоматический первый запуск до настройки переменных и базы.
4. Подключите Postgres addon; если используется Supabase, добавьте `DATABASE_URL` вручную. Строку базы не публикуйте.
5. Создайте в Supabase Storage private bucket `nimb` и S3-ключи; в Brevo подтвердите отправителя и включите транзакционную отправку. Доступ Brevo может потребовать проверки.
6. В настройках Environment укажите `APP_ORIGIN` как точный HTTPS-адрес сайта (без завершающего `/`), `MAIL_PROVIDER=brevo`, `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_CREATE_BUCKET=false`. Секреты вводите только в панели сервиса; не отправляйте их в чат и не загружайте в GitHub.
7. Стандартный `npm run build` генерирует Prisma Client и собирает клиент с сервером; `npm start` применяет миграции и запускает приложение. База должна быть доступна во время запуска.
8. Только после настройки всех переменных выполните deploy и проверьте реальную доставку писем, работу WebSocket на двух устройствах, хранение файлов после перезапуска и лимиты памяти. Если сборка или работа превысят бесплатные лимиты, потребуется другой хостинг.
9. Зарегистрируйте свой аккаунт, найдите ID в профиле и задайте `ADMIN_USER_IDS` в приватных переменных. Перезапустите сервис.

Не храните важные данные без независимой резервной копии. Автоматические бэкапы и политика бесплатного тарифа должны быть проверены в панели провайдера.
