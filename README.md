# nimb

Развиваемый веб-мессенджер на React, TypeScript, Vite, Fastify, Socket.IO, PostgreSQL и Prisma. Текущая версия предназначена для разработки и не является законченной реализацией всего технического задания или готовым публичным сервисом.

## Что реализовано

- Регистрация с подтверждением email, вход, восстановление и смена пароля; управление активными сеансами и выход. Письма отправляются через SMTP. При смене и восстановлении пароля другие или все сеансы соответственно отзываются.
- Поиск пользователей, просмотр профилей, изменение имени и описания, аватар и баннер, HTTPS-ссылки, настройка видимости описания и статуса онлайн, ограничение личных сообщений, подписки, блокировки и сохранение жалоб. Изображения проверяются по содержимому и преобразуются в WebP; обновления профиля передаются собеседникам и подписчикам. Жалобы доступны в панели администратора.
- Личные сообщения с сохранением в PostgreSQL и событиями Socket.IO; редактирование и удаление своих сообщений, ответы, пересылка текста и вложений, реакции, закрепление, поиск, индикатор набора текста и отметки отправки, доставки и прочтения в личных чатах. Старые сообщения и результаты поиска загружаются страницами по 50.
- Группы и каналы с приглашением по ссылке, ролями владельца, администратора и участника, изменением названия и описания, назначением администраторов и удалением участников. В канале публикуют только владелец и администраторы. Аватар и баннер сообщества могут менять владелец и администраторы; просмотры публикаций считаются по уникальным участникам, загрузившим их.
- Вложения JPEG, PNG, WebP и PDF до 5 МиБ в чатах, с проверкой сигнатуры файла и доступом только участникам. Файлы хранятся в S3-совместимом хранилище.
- Лента текстовых публикаций и изображений, подписки, поиск по тексту и тегам, лайки, комментарии, удаление своих публикаций и подгрузка страниц при прокрутке.
- Настройки шрифта, размера текста, уменьшения движения, фона чата, личные папки, браузерные уведомления и Web Push при настроенных VAPID-ключах. Настройки отображения сохраняются на устройстве.
- Коллекционные подарки с экземплярами и историей выдачи; владелец может закрепить до трёх. Подарки бесплатны и не продаются, передача существующих экземпляров не реализована. Значки раннего участника и автора канала выдаются сервером автоматически.
- Музыкальная карточка профиля с загрузкой собственного MP3 и обложки после подтверждения прав на распространение.
- Адаптивный интерфейс, PWA-манифест и service worker; установка зависит от поддержки браузера и HTTPS. Автономная переписка не реализована.

Пароли хешируются Argon2id. Токены сессий и одноразовых ссылок хранятся в БД только в виде хешей. Сессия передаётся в HttpOnly/SameSite cookie; изменяющие запросы проверяют Origin, а работа с чатами, сообщениями и файлами — членство и роли. Эти меры не заменяют полноценный аудит безопасности.

## Запуск всего стека через Docker Compose

Подготовлен профиль для запуска без отдельных Node-процессов. Образы собирались, но в текущем окружении создание контейнера не удалось проверить из-за нехватки места на диске:

```sh
cp .env.example .env
docker compose --profile app up --build -d --wait
```

Откройте http://localhost:8081; письма подтверждения доступны в Mailpit на http://localhost:8025. При старте API автоматически применяет миграции. Этот профиль использует локальные тестовые Mailpit и S3Mock и не предназначен для публичного развёртывания. Для Web Push дополнительно задайте VAPID-ключи в `.env` и пересоздайте API. Остановка без удаления данных: `docker compose --profile app down`.

## Запуск для разработки

Нужны Node.js 20+, npm и Docker с Compose. В корне проекта:

```sh
cp .env.example .env
npm install
docker compose up -d --wait
npm run db:generate
npm run db:migrate
npm run setup:push  # необязательно: явная VAPID-пара для нового локального развёртывания
npm run dev
```

Откройте http://localhost:5173. API работает на порту 3000. Контейнер Mailpit принимает письма локально: откройте http://localhost:8025, чтобы перейти по ссылке подтверждения или восстановления пароля. Это тестовая почта: реальные письма наружу она не доставляет. Для проверки переписки используйте два браузера или обычное и приватное окна.

В Docker Compose используются PostgreSQL, Mailpit и S3Mock. S3Mock — локальная тестовая реализация S3, не предназначенная для публичного развёртывания. Данные PostgreSQL и файлов сохраняются в Docker volumes. Остановка: `docker compose down`; добавление `-v` удалит тома и данные.

Если обновляете прежний MVP, после миграции существующим аккаунтам необходимо подтвердить email. На странице входа есть кнопка повторной отправки письма.

## Тесты

Запустите контейнеры, примените миграции и запустите API (`npm run dev -w @nimb/api`). Тесты создают и удаляют свои записи; выполняйте их на отдельной тестовой базе, а не на базе с важными данными.

```sh
npm run build
npm test
npm run test:e2e
```

Интеграционный тест использует Mailpit на `localhost:8025` и S3Mock, проверяет подтверждение и восстановление доступа, приватность описания, загрузку и удаление изображений профиля, постраничную историю, пересылку файлов, выдачу и закрепление подарков, значки, просмотры канала, музыку, папки, настройки личных сообщений, права чатов и каналов, события Socket.IO, вложения, блокировки, ленту и сеансы. Отдельный тест проверяет регистрацию push-подписки, фильтрацию адресов и удаление подписки при выходе; доставка через внешнюю push-службу не проверялась. Повторные запуски подряд могут временно встретить ограничение частоты регистрации; дождитесь окончания минуты. E2E-тест запускает Vite и Chromium, создаёт двух пользователей и проверяет переписку, пересылку, загрузку ранних сообщений и сохранение настроек на размерах экрана ПК и телефона; также проверяет фото в ленте, подарки, музыку с обложкой и приватность. По умолчанию используется `/usr/bin/chromium`; задайте `CHROMIUM_PATH`, если браузер расположен иначе.

## Что ещё не реализовано

Панель модерации позволяет просматривать и закрывать жалобы и ограничивать аккаунты; журнала действий администраторов пока нет. Нет распределённого ограничения частоты, передачи существующих экземпляров подарков, полного набора видов значков и расширенной настройки профиля. Статус онлайн работает в рамках одного процесса API; в многопроцессном развёртывании требуется общее хранилище присутствия. Не реализовано сквозное шифрование. Не завершены общие типизированные контракты и модульная архитектура, полноценное покрытие unit/E2E-тестами и аудит безопасности. Другие языки интерфейса, кроме русского, пока не реализованы.

## Развёртывание

Публичное развёртывание пока не рекомендуется. Зависимость `deepmerge-ts` для Prisma CLI закреплена через npm override на исправленной версии 8; совместимость следует перепроверять при обновлении Prisma. До него необходимо реализовать недостающие средства приватности и модерации, проверить безопасность загрузок и сессий, добавить мониторинг, резервное копирование и провести независимый аудит. Для будущего VPS потребуются HTTPS и reverse proxy с поддержкой WebSocket, приватная PostgreSQL, настоящий S3-совместимый сервис с закрытым bucket и SMTP-провайдер. Задайте `NODE_ENV=production`, HTTPS `APP_ORIGIN`, защищённый `DATABASE_URL`, `SMTP_HOST`, `SMTP_PORT`, при необходимости `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_SECURE=true`, `MAIL_FROM`, а также `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`. Web Push автоматически создаёт и сохраняет единственную пару VAPID-ключей в серверной таблице `WebPushConfig`, если переменные VAPID не заданы. Пара сохраняется при перезапусках и общая для экземпляров приложения; приватный ключ никогда не передаётся клиенту. Можно явно задать полную пару `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`; частичная или несовместимая пара отключает push с ошибкой в журнале. Команда `npm run setup:push` предназначена для явной настройки нового локального развёртывания; при работающих push не меняйте пару. Регистрация требует HTTPS или localhost. На iPhone/iPad (iOS 16.4+) откройте установленную на главный экран PWA и разрешите уведомления в Настройки → Уведомления. Там же есть тестовая отправка. Отключите `S3_CREATE_BUCKET` и создайте bucket и права доступа отдельно. Храните секреты вне Git и замените все локальные учётные данные. После `npm run build` раздавайте `apps/web/dist`, а `/api` и `/socket.io` проксируйте к `npm run start -w @nimb/api`. Пример Compose предназначен только для разработки.


### Администраторы и модерация

После регистрации и подтверждения почты найдите числовой ID аккаунта в своём профиле. Укажите доверенные ID через запятую в `ADMIN_USER_IDS` в серверном `.env`, например `ADMIN_USER_IDS="1,2"`, и перезапустите API. При запуске через Docker Compose переменная передаётся в контейнер. Пункт «Администрирование» появится в настройках указанных аккаунтов. Доступ проверяется сервером на каждом запросе.

Панель показывает последние 100 пользователей и открытых жалоб, позволяет отмечать жалобы рассмотренными, ограничивать аккаунты и восстанавливать доступ. При ограничении активные сессии и соединения отключаются; администраторов из списка ограничить нельзя. Владельцы сообществ могут назначать администраторов и управлять участниками через информацию о сообществе.

### Публичный показ

Файл `nimb-preview.html` предназначен только для показа интерфейса без сервера; чаты и учётные записи в нём не работают. Для работающего мессенджера необходим постоянный сервер Node.js с HTTPS, PostgreSQL, настоящим SMTP и S3-совместимым хранилищем. GitHub Pages может разместить только статический интерфейс и сам по себе не запускает сервер мессенджера. Текущий Docker Compose с Mailpit и S3Mock предназначен для локальной разработки. Для публичного запуска нужна отдельная настройка продакшн-сервисов и проверка безопасности; готовой публичной ссылки в архиве нет.

### Установка на телефон

Откройте работающий Nimb по HTTPS на телефоне. В настройках приложения выберите «Установить приложение»: на поддерживаемом Android-браузере появится кнопка установки, на iPhone показаны шаги для Safari. В Safari можно нажать «Поделиться» → «На экран Домой»; в Chrome на Android — меню → «Установить приложение» или «Добавить на главный экран». Доступность установки зависит от браузера. HTML-файл предпросмотра работает только как просмотр и не устанавливается как приложение.

Для подготовки бесплатного пробного запуска см. [RENDER_SETUP.md](RENDER_SETUP.md).
